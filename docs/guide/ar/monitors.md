# المراقبات

## القائمة

تعرض قائمة المراقبات **أصل** كل مراقبة و**التطبيقات** التي تنتمي إليها (للعضوية الاختيارية إطار متقطع)، وكلاهما رابط. انقر عنوان عمود للترتيب (مرة أخرى للعكس، ومرة ثالثة للترتيب الافتراضي)، ويتذكر Fudo الترتيب في هذا المتصفح. يبحث مربع التصفية في الأسماء والأهداف والوسوم والأصول والتطبيقات، ويتجاهل حالة الأحرف والتشكيل، ويجب أن تطابق كل كلمة. وتُرتَّب القوائم الطويلة الأخرى (الأصول، الحوادث، المستخدمون، الصيانة، القنوات وغيرها) وتُصفّى بالطريقة نفسها.

## أنواع المراقبات

| الفئة | النوع | يفحص |
|---|---|---|
| الويب | **HTTP(S)** | نطاقات رموز الحالة، ووجود كلمة مفتاحية أو غيابها، وقيمة JSON (`$.status`)، والترويسات، والمحتوى، وزمن الاستجابة |
| | **شهادة TLS** | الثقة واسم المضيف والأيام المتبقية حتى الانتهاء (متدهور خلال N يومًا، متوقف عند الانتهاء) |
| الشبكة | **Ping** | إمكانية الوصول والتأخير وفقدان الحزم |
| | **منفذ TCP** | المنفذ يقبل الاتصالات |
| | **DNS** | A/AAAA/CNAME/MX/TXT/NS، مع إجابة متوقعة اختيارية ومحلِّل مختار |
| | **SNMP** | يقرأ OID (v1، v2c، v3) ويقارن القيمة أو، للعدّادات، تغيّرها في الثانية |
| | **واجهة شبكة (SNMP)** | منفذ مبدّل أو موجّه أو جدار حماية: حالة الوصلة، حركة البيانات الواردة والصادرة (bit/s ونسبة من سرعة الوصلة)، الأخطاء؛ مع رسم بياني عبر الزمن |
| | **NTP** | إمكانية الوصول وstratum وانحراف الساعة |
| | **SMTP** | تحية 220 وEHLO وSTARTTLS اختياريًا |
| | **LDAP / Active Directory** | الدليل يستجيب (Active Directory: متدهور ما دامت وحدة التحكم بالمجال غير متزامنة)، أو يسجّل حساب الدخول ويعثر بحث على إدخالات؛ ويبيّن الحسابات المقفلة والمنتهية والمعطّلة |
| | **انتهاء النطاق** | انتهاء التسجيل عبر RDAP (مع WHOIS بديلًا) |
| قواعد البيانات | **PostgreSQL وMySQL/MariaDB وMicrosoft SQL Server وMongoDB وRedis** | يتصل، مع استعلام اختياري ونتيجة متوقعة |
| الأنظمة | **أمر SSH** | رمز الخروج أو المخرجات (يحتوي، مطابق، تعبير نمطي)، مع تثبيت اختياري لمفتاح المضيف |
| | **حاوية Docker** | تعمل، وسليمة إن كان لها فحص صحة |
| البنية التحتية | **آلة افتراضية في vCenter** | حالة الطاقة وVMware Tools (vCenter 6.7 و7 و8) |
| | **صحة HPE iLO / Redfish** | صحة عتاد الخادم من وحدة BMC (iLO 4/5/6 وiDRAC ووحدات BMC الأخرى الداعمة لـRedfish) |
| | **درجة حرارة الدخول (iLO / Redfish)** | درجة حرارة الهواء الداخل إلى الخادم، أي أمام خزانته: متدهور من 27 °C، ومتوقف من 32 °C ‏(ASHRAE)، مع رسم بياني |
| | **حرارة الغرفة** | جميع مستشعرات الدخول الموسومة `room:<name>` معًا: متوقف عندما تسخن عدة مستشعرات (مشكلة تبريد)، ومتدهور عندما يسخن واحد أو يرتفع عدد منها بسرعة |
| سلبية | **نبضات Push** | تستدعي مهمةٌ عنوان URL؛ متوقف حين تتوقف الاستدعاءات |
| | **SNMP traps** | traps يرسلها جهاز (v1، v2c): متوقف أو متدهور ما دام هناك trap مشكلة مفتوح؛ ينتهي تلقائيًا أو بـtrap إنهاء أو يدويًا |

يشغّل **اختبار الآن** فحصًا مرة واحدة من خادم Fudo دون حفظه، لتضبطه قبل أن يبدأ بإرسال الإشعارات.

## تجنّب الإنذارات الكاذبة

- **متوقف بعد N إخفاقات**: لا تصبح المراقبة متوقفة إلا بعد N فحوص فاشلة متتالية، وتعيد المحاولة في
  الأثناء على *فاصل إعادة المحاولة* الأقصر.
- **يعمل بعد M نجاحات**: لا تتعافى إلا بعد M فحوص ناجحة متتالية.
- **متدهور فوق**: تُعدّ الاستجابات البطيئة متدهورة بدلًا من متوقفة.

## بيانات الاعتماد

تُخزَّن كلمات المرور ومجتمعات SNMP ومفاتيح SSH وما شابهها **مشفّرة**، ولا تُعرض أو تُصدَّر أو تُعاد من
API أبدًا بعد ذلك؛ وحده الـworker يفك تشفيرها لتشغيل الفحص. استخدم حسابات للقراءة فقط: دور
*Read-only* في vCenter، ومستخدم iLO بصلاحية *Login*، ومستخدم قاعدة بيانات بصلاحيات `CONNECT`/`SELECT`
فقط.

### بيانات الاعتماد المشتركة

عندما تسجّل مراقبات كثيرة الدخول بالحساب نفسه (مستخدم iLO واحد للقراءة فقط لكل الخوادم، أو مجتمع
SNMP واحد للمبدّلات)، احفظه مرة واحدة في **بيانات الاعتماد** ودع المراقبات تستخدمه. وعندما تتغيّر
كلمة المرور، عدّل بيانات الاعتماد مرة واحدة: تعيد كل مراقبة تستخدمها الفحص فورًا بالقيمة الجديدة.

- لبيانات الاعتماد نوع: *الحساب وكلمة المرور* أو *مفتاح SSH* أو *مجتمع SNMP (v1، v2c)* أو
  *مستخدم SNMPv3*. في نموذج المراقبة، تعرض الأنواع التي تسجّل الدخول **إدخاله هنا** أو **استخدام
  بيانات اعتماد مشتركة**؛ ومع بيانات الاعتماد تختفي حقول الحساب من النموذج.
- تتبع بيانات الاعتماد نطاقًا واحدًا: لا تستطيع مراقبات المستأجر استخدام إلا بيانات اعتماد هذا
  المستأجر، ولا تستخدم مراقبات نطاق البنية التحتية العامة إلا البيانات العامة.
- الأسرار للكتابة فقط، مثل أسرار المراقبة: تُخزَّن مشفّرة ولا تُعرض أو تُصدَّر أو تُعاد أبدًا. تعرض
  القائمة الحساب والمراقبات التي تستخدمه.
- **الحساب نفسه في عدة مراقبات**: تعرض الصفحة المراقبات التي تخزّن بالفعل الحساب وكلمة المرور
  نفسيهما. أعطِ المجموعة اسمًا واختر **إنشاء بيانات اعتماد مشتركة**: تُنسخ كلمة المرور على الخادم،
  ولا يحتاج أحد إلى معرفتها.
- يربط **استخدام لـ…** مزيدًا من المراقبات ببيانات الاعتماد؛ ويُزال حسابها وكلمة مرورها الخاصان.
  لا يمكن حذف بيانات اعتماد قيد الاستخدام، ولا تغيير نوعها.
- المراقبة التي تتوقف عن استخدام بيانات الاعتماد تحتاج من جديد إلى كلمة مرورها الخاصة.
- في [الإعداد كرمز](configuration-as-code.md) تذكر المراقبة بيانات اعتمادها بالاسم
  (`credential: iLO read-only`)؛ أما بيانات الاعتماد نفسها فتُنشأ في الواجهة. ويمكن للإضافة
  المجمّعة لفحوص الحرارة استخدامها أيضًا.
- يُسجَّل كل تغيير في سجل التدقيق، مع أسماء الأسرار التي تغيّرت، وليس قيمها أبدًا.

## مراقبات Push

تنتظر مراقبة Push أن تستدعيها مهمتك. بعد الحفظ تعرض صفحتها عنوان URL:

```bash
curl -fsS "https://fudo.corp.local/api/push/<token>?msg=backup%20ok&ping=5400"   # success
curl -fsS "https://fudo.corp.local/api/push/<token>?status=down&msg=disk%20full" # report a failure
```

تصبح متوقفة إذا لم يصل أي استدعاء خلال الفاصل مضافًا إليه مهلة السماح. يستبدل **عنوان URL جديد**
الرمز إذا تسرّب.

## الإضافة بالجملة والقوالب

تنشئ **المراقبات › إضافة بالجملة / قوالب** فحوصًا لعدد كبير من المضيفات دفعة واحدة:

1. الصق مضيفًا أو عنوان URL في كل سطر (أو حمّل ملف CSV يتضمن `name,host,port`)،
2. اختر **قالبًا**، مثل *خادم Windows* (ping وRDP وWinRM) أو *خادم Linux* أو *HPE iLO* أو *جهاز شبكة*
   أو *مضيف ESXi* أو *vCenter* أو *SQL Server* أو *نظام تخزين* أو *تطبيق ويب*، أو نوع فحص واحدًا،
3. اختياريًا أنشئ أصلًا لكل سطر، واجعلها تعتمد على أصل موجود، وأضفها إلى تطبيق.

يعرض قبل التطبيق معاينة لكل ما سيُنشأ.

## ملاحظات حسب النوع

- **آلة افتراضية في vCenter** تجد إصدار API المناسب بنفسها وتعيد استخدام الجلسات (تسجيل دخول واحد
  لكل vCenter كل 20 دقيقة). يتطلب فحص VMware Tools الإصدار vCenter 7.0 أو أحدث.
- **HPE iLO / Redfish** يسمّي في HPE iLO الجزء المعطّل (المراوح ومزودات الطاقة والتخزين والتكرار).
  Warning ← متدهور، وCritical أو الإطفاء ← متوقف.
- **أمر SSH**: اضبط *بصمة مفتاح المضيف* (`ssh-keyscan host | ssh-keygen -lf -`) حتى يُبلَّغ عن تغيّر
  مفتاح الخادم بدلًا من قبوله.
- **حاوية Docker** تستخدم مقبس Docker المحلي (اربطه بحاوية الـworker، راجع `docker-compose.yml`) أو
  عنوان URL لواجهة Docker API بعيدة.
- **انتهاء النطاق**: لا تنشر بعض السجلات الوطنية RDAP ولا WHOIS؛ يبلّغ Fudo عن ذلك بحالة متدهور مع
  شرح.
- يحتاج **Ping** إلى صلاحية `NET_RAW` في حاوية الـworker، وفي حاوية API من أجل **اختبار الآن** (كلتاهما
  مضبوطتان في `docker-compose.yml`).

## SNMP traps

وجّه SNMP traps (v1 أو v2c) من أجهزتك إلى خادم Fudo، منفذ UDP 162. تعرض صفحة **Traps** ما إذا
كانت الـtraps تُستقبل، وكل trap مع حقوله.

- تأخذ مراقبة **SNMP traps** الـtraps من الأجهزة في **من**: عناوين أو أسماء مضيفين أو نطاقات
  IPv4 (`10.0.12.0/24`). ومع **مجتمع** (أو بيانات اعتماد مشتركة من نوع مجتمع SNMP) تأخذ فقط
  الـtraps التي تحمله؛ ولا يُخزَّن المجتمع أبدًا.
- **traps المشكلات**: القياسية (link down، التشغيل البارد والدافئ، فشل المصادقة)، أو الـtraps
  المدرجة فقط (أسماء أو OID؛ ويشمل الـOID أيضًا كل ما تحته، مثل بادئة enterprise لمصنّع)، أو أي
  trap. ويقصر *فقط عندما يحتوي حقل على* الأمرَ على الـtraps التي تحوي نصًا مثل `Critical`.
- ما دامت هناك مشكلة مفتوحة تكون المراقبة **متوقفة** (أو متدهورة، إن اخترت ذلك)؛ وتعمل الحادثة
  والإشعارات والمناوبات كما في أي فحص، خلال ثانية من وصول الـtrap.
- تُتابَع المشكلات لكل trap وواجهة: link down على منفذين مشكلتان، و**link up** لمنفذ ينهي مشكلة
  ذلك المنفذ فقط.
- **تنتهي المشكلات** تلقائيًا عندما لا يصل trap جديد لبعض الوقت (افتراضيًا 30 دقيقة)، أو يدويًا
  فقط: تعرض صفحة المراقبة الـtraps المفتوحة مع زر **مسح** (حتى الـtrap المطابق التالي). وتنهي
  *traps الإنهاء* المشكلات أيضًا، مثل trap «زالت الحالة» لدى مصنّع.
- الـtrap الذي **لا تأخذه أي مراقبة** يُحفظ مع ذلك: لدى مستأجر الأصل الذي يحمل ذلك العنوان، وإلا
  ففي نطاق البنية التحتية العامة. ويملأ **إنشاء مراقبة** في صفحة Traps مراقبةً لجهازه.
- يُقيَّد الجهاز الذي يُغرق بالـtraps (50 في الثانية، وذروات حتى 500)؛ وتُعدّ الـtraps المُسقطة في
  صفحة Traps للنطاق العام. وتُحفظ الـtraps لمدة 30 يومًا (الإعدادات › الاحتفاظ بالبيانات).

## واجهات الشبكة

تراقب مراقبة **واجهة شبكة (SNMP)** منفذًا واحدًا لمبدّل أو موجّه أو جدار حماية.

- يعرض **العثور على الواجهات…** (بعد المضيف ووصول SNMP، أو بيانات اعتماد مشتركة) واجهات الجهاز
  مع الوصف والسرعة والحالة. اختر واحدة، أو حدّد عدة واجهات عند الإضافة: تصبح كل واحدة مراقبة
  بإعدادات النموذج، باسم الواجهة.
- تُحفظ الواجهة **باسمها** (أو وصفها أو اسمها البديل)، لا برقمها، لأن بعض الأجهزة تعيد ترقيم
  واجهاتها بعد إعادة التشغيل. والرقم يعمل أيضًا.
- **حركة البيانات** هي الفرق بين قراءتين لعدّادات 64 بت: يقرأ الفحص الأول مرتين بفاصل ثانيتين؛
  وتستخدم الفحوص اللاحقة القراءة المحفوظة من الفحص السابق. بعد إعادة تشغيل الجهاز يُتجاهل الزوج،
  فلا تظهر قفزة زائفة. تستخدم الأجهزة التي لا تملك عدّادات 64 بت (SNMP v1) عدّادات 32 بت، وهي غير
  موثوقة فوق نحو 100 Mbit/s مع فاصل دقيقة واحدة.
- **الحالة**: انقطاع الوصلة ← متوقف؛ testing أو dormant ← متدهور؛ المنفذ المعطّل عن قصد يعمل
  (أو متوقف، إن اخترت ذلك). الاتجاه الأكثر انشغالًا فوق *متدهور ابتداءً من استخدام* (افتراضيًا
  80 %) ← متدهور، وفوق *متوقف ابتداءً من استخدام* (متوقف افتراضيًا) ← متوقف؛ والأخطاء في الدقيقة
  فوق الحد ← متدهور. إذا أبلغ الجهاز عن سرعة خاطئة (نفق، دارة محدودة المعدّل)، فاضبط *سرعة
  الوصلة*.
- تعرض صفحة المراقبة حركة البيانات الواردة والصادرة مع خط حالة متدهور.
- يفعل *المقارنة: تغيّرها في الثانية* في مراقبة **SNMP** الشيء نفسه لأي عدّاد (الإطارات على منفذ
  SAN، جلسات جدار الحماية، أحداث مزوّد الطاقة غير المنقطعة).

## حرارة مركز البيانات

تعرض **الحرارة** كل مستشعر لحرارة الدخول مجمّعًا حسب الوسم `room:<name>` ومرتبًا من الأدفأ، مع خزانته (`rack:<name>`) وقيمته الحالية وآخر 6 ساعات والتغيّر خلال 15 دقيقة ونطاق 24 ساعة. وتُنشئ **إضافة مستشعرات** المستشعرات لقائمة عناوين iLO (أو BMC أخرى تدعم Redfish) بحساب مشترك للقراءة فقط.

ويصبح المستشعر متدهورًا أيضًا عندما **ترتفع** حرارته **بسرعة** (افتراضيًا 3 °C خلال 15 دقيقة) حتى دون حدوده: أول علامة على عطل في التبريد. ويضيف **إنشاء تنبيه للغرفة** مراقبة *حرارة الغرفة*: متوقف عندما يسخن 3 مستشعرات، ومتدهور عندما يسخن واحد أو يرتفع 2 بسرعة. وتفتح حوادث كأي مراقبة، فتعمل لها كذلك الملكية والمناوبات وصفحات الحالة.
