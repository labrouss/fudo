# Конфигурация като код

**Конфигурация** експортира текущия обхват (ресурси, монитори, приложения и техните зависимости)
като YAML и го импортира обратно. Пазете го в git, копирайте настройката на един наемател в друг или
я автоматизирайте чрез API.

```yaml
assets:
  - name: FIN-APPLIANCE-01
    kind: other
    dependsOn: [Core-SW-01]          # shared assets are referenced by name
monitors:
  - name: ERP web
    type: http
    config: { url: https://erp.corp.local/health, acceptedStatus: 200-299 }
    asset: FIN-APPLIANCE-01          # the asset this monitor checks
    tags: [prod]
applications:
  - name: ERP Production
    criticality: high
    slaTarget: 99.9
    members: [ERP web, { monitor: ERP SQL, required: false }]
    notify: [ERP team]               # notification channels, by name
```

## Как работи импортът

- **Първо преглед**: показва поле по поле какво ще бъде създадено или променено и съобщава грешките
  с номера на реда. **Прилагане** става изцяло или изобщо не става.
- **Частичните файлове са безопасни**: елемент във файла определя този елемент; елементите, които ги
  няма във файла, остават каквито са.
- **Не са включени**: каналите за известия и идентификационните данни (съдържат тайни), както и
  прозорците за поддръжка. Импортираните push монитори получават нови URL адреси. Приложенията
  посочват каналите си по име в `notify`; без `notify` приложението запазва текущите си канали.
- **Споделени идентификационни данни**: мониторът посочва използваните по име (`credential: iLO
  read-only`). Самите данни не се експортират и трябва вече да съществуват в целевия обхват.

## Чрез API

```bash
curl -fsS -X POST https://fudo.corp.local/api/config/import \
  -H "Authorization: Bearer fudo_…" -H "X-Fudo-Tenant: <tenant id>" \
  -H "Content-Type: application/json" -d '{"yaml": "…", "dryRun": true}'
```

Изисква API токен с правото **Управление** (вижте [Потребители и достъп](users-and-access.md)).

## Импорт от Uptime Kuma

**Конфигурация › Импорт от Uptime Kuma** чете JSON резервното копие на Uptime Kuma 1.x (*Настройки › Резервно копие › Експорт*) или файла на базата данни `kuma.db` на версии 1.x и 2.x (в папката с данни на Kuma). Първо виждате преглед; нищо не се променя до импорта.

Проверките по HTTP, ключова дума и прост JSON, TCP порт, ping, DNS и push се импортират с интервалите, повторенията, етикетите и състоянието на пауза; изтичането на HTTPS сертификати става отделен монитор за сертификат, а групите стават приложения. Известията стават канали със същите настройки (имейл известията използват пощенския сървър от Настройки) и започват изключени, освен ако не изберете друго. Елементи, чието име вече съществува, не се пипат, така че повторният импорт е безопасен. Всичко, което не може да се импортира вярно (например монитори за Docker или бази данни, или обърнатият режим), се показва с причината.
