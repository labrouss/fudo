# Διαμόρφωση ως κώδικας

Η **Διαμόρφωση** εξάγει το τρέχον πεδίο (πόρους, παρακολουθήσεις, εφαρμογές και τις εξαρτήσεις
τους) ως YAML και το εισάγει ξανά. Κρατήστε το στο git, αντιγράψτε τη ρύθμιση ενός μισθωτή σε
άλλον, ή αυτοματοποιήστε τη μέσω του API.

```yaml
assets:
  - name: FIN-APPLIANCE-01
    kind: other
    dependsOn: [Core-SW-01]          # shared assets are referenced by name
monitors:
  - name: ERP web
    type: http
    config: { url: https://erp.corp.local/health, acceptedStatus: 200-299 }
    asset: FIN-APPLIANCE-01          # the asset this monitor checks
    tags: [prod]
applications:
  - name: ERP Production
    criticality: high
    slaTarget: 99.9
    members: [ERP web, { monitor: ERP SQL, required: false }]
    notify: [ERP team]               # notification channels, by name
```

## Πώς λειτουργεί η εισαγωγή

- **Πρώτα προεπισκόπηση**: δείχνει τι θα δημιουργηθεί ή θα αλλάξει, πεδίο προς πεδίο, και
  αναφέρει τα λάθη με τον αριθμό γραμμής τους. Η **Εφαρμογή** γίνεται ολόκληρη ή καθόλου.
- **Τα μερικά αρχεία είναι ασφαλή**: ένα στοιχείο του αρχείου καθορίζει πλήρως αυτό το
  στοιχείο· όσα δεν υπάρχουν στο αρχείο μένουν όπως είναι.
- **Δεν περιλαμβάνονται**: κανάλια ειδοποιήσεων και διαπιστευτήρια (περιέχουν μυστικά) και
  παράθυρα συντήρησης. Οι εισαγόμενες παρακολουθήσεις push παίρνουν νέα URL. Οι εφαρμογές
  αναφέρουν τα κανάλια τους με το όνομα στο `notify`· αν παραλείψετε το `notify`, μια
  εφαρμογή κρατά τα τρέχοντα κανάλια της.
- **Κοινά διαπιστευτήρια**: μια παρακολούθηση αναφέρει με το όνομα αυτά που χρησιμοποιεί
  (`credential: iLO read-only`). Τα ίδια τα διαπιστευτήρια δεν εξάγονται και πρέπει να υπάρχουν ήδη στο πεδίο προορισμού.

## Μέσω του API

```bash
curl -fsS -X POST https://fudo.corp.local/api/config/import \
  -H "Authorization: Bearer fudo_…" -H "X-Fudo-Tenant: <tenant id>" \
  -H "Content-Type: application/json" -d '{"yaml": "…", "dryRun": true}'
```

Απαιτεί διακριτικό API με δικαίωμα **Διαχείριση** (δείτε [Χρήστες και πρόσβαση](users-and-access.md)).

## Εισαγωγή από το Uptime Kuma

Η **Διαμόρφωση › Εισαγωγή από το Uptime Kuma** διαβάζει το αντίγραφο JSON του Uptime Kuma 1.x (*Ρυθμίσεις › Αντίγραφο ασφαλείας › Εξαγωγή*) ή το αρχείο βάσης δεδομένων `kuma.db` των εκδόσεων 1.x και 2.x (στον φάκελο δεδομένων του Kuma). Βλέπετε πρώτα προεπισκόπηση· τίποτα δεν αλλάζει μέχρι να κάνετε εισαγωγή.

Οι έλεγχοι HTTP, λέξης-κλειδιού και απλού JSON, θύρας TCP, ping, DNS και push εισάγονται με τα διαστήματα, τις επαναλήψεις, τις ετικέτες και την κατάσταση παύσης τους· η λήξη πιστοποιητικού HTTPS γίνεται χωριστή παρακολούθηση πιστοποιητικού και οι ομάδες γίνονται εφαρμογές. Οι ειδοποιήσεις γίνονται κανάλια με τις ίδιες ρυθμίσεις (όσες είναι email χρησιμοποιούν τον διακομιστή αλληλογραφίας των Ρυθμίσεων) και ξεκινούν απενεργοποιημένα, εκτός αν επιλέξετε αλλιώς. Στοιχεία με όνομα που υπάρχει ήδη δεν αγγίζονται, οπότε μια νέα εισαγωγή είναι ασφαλής. Ό,τι δεν μπορεί να εισαχθεί πιστά (για παράδειγμα παρακολουθήσεις Docker ή βάσεων δεδομένων, ή η ανεστραμμένη λειτουργία) εμφανίζεται με την αιτία.
