# Παρακολουθήσεις

## Η λίστα

Η λίστα παρακολουθήσεων δείχνει τον **πόρο** κάθε παρακολούθησης και τις **εφαρμογές** στις οποίες ανήκει (η προαιρετική συμμετοχή έχει διακεκομμένο περίγραμμα)· και τα δύο είναι σύνδεσμοι. Πατήστε την επικεφαλίδα μιας στήλης για ταξινόμηση (ξανά για αντίστροφη σειρά, τρίτη φορά για την προεπιλεγμένη)· το Fudo θυμάται την ταξινόμηση σε αυτόν τον browser. Το πεδίο φίλτρου αναζητά ονόματα, στόχους, ετικέτες, πόρους και εφαρμογές· αγνοεί πεζά-κεφαλαία και τόνους, και πρέπει να ταιριάζει κάθε λέξη. Οι άλλες μεγάλες λίστες (πόροι, συμβάντα, χρήστες, συντηρήσεις, κανάλια και άλλες) ταξινομούνται και φιλτράρονται με τον ίδιο τρόπο.

## Τύποι παρακολούθησης

| Κατηγορία | Τύπος | Ελέγχει |
|---|---|---|
| Ιστός | **HTTP(S)** | εύρη κωδικών κατάστασης, λέξη-κλειδί παρούσα/απούσα, τιμή JSON (`$.status`), κεφαλίδες, σώμα, χρόνο απόκρισης |
| | **Πιστοποιητικό TLS** | εμπιστοσύνη, όνομα host, ημέρες έως τη λήξη (Υποβαθμισμένο εντός N ημερών, Εκτός λειτουργίας όταν λήξει) |
| Δίκτυο | **Ping** | προσβασιμότητα, καθυστέρηση, απώλεια πακέτων |
| | **Θύρα TCP** | η θύρα δέχεται συνδέσεις |
| | **DNS** | A/AAAA/CNAME/MX/TXT/NS, προαιρετικά αναμενόμενη απάντηση, επιλεγμένος διακομιστής |
| | **SNMP** | διαβάζει ένα OID (v1, v2c, v3) και συγκρίνει την τιμή ή, για μετρητές, τη μεταβολή της ανά δευτερόλεπτο |
| | **Διεπαφή δικτύου (SNMP)** | μια θύρα μεταγωγέα, δρομολογητή ή τείχους προστασίας: κατάσταση σύνδεσης, κίνηση εισερχόμενη και εξερχόμενη (bit/s και % της ταχύτητας σύνδεσης), σφάλματα· με γράφημα στον χρόνο |
| | **NTP** | προσβασιμότητα, stratum, απόκλιση ρολογιού |
| | **SMTP** | χαιρετισμός 220, EHLO, προαιρετικά STARTTLS |
| | **LDAP / Active Directory** | ο κατάλογος απαντά (Active Directory: Υποβαθμισμένο όσο ο ελεγκτής τομέα δεν είναι συγχρονισμένος) ή ένας λογαριασμός συνδέεται και μια αναζήτηση βρίσκει εγγραφές· αναφέρει κλειδωμένους, ληγμένους και απενεργοποιημένους λογαριασμούς |
| | **Λήξη τομέα** | λήξη καταχώρισης μέσω RDAP (εναλλακτικά WHOIS) |
| Βάσεις δεδομένων | **PostgreSQL, MySQL/MariaDB, Microsoft SQL Server, MongoDB, Redis** | συνδέεται, προαιρετικό ερώτημα με αναμενόμενο αποτέλεσμα |
| Συστήματα | **Εντολή SSH** | κωδικό εξόδου ή έξοδο (περιέχει, ακριβής, regex), προαιρετικό καρφίτσωμα κλειδιού host |
| | **Container Docker** | εκτελείται, και είναι υγιές αν έχει έλεγχο υγείας |
| Υποδομή | **VM vCenter** | κατάσταση τροφοδοσίας, VMware Tools (vCenter 6.7, 7, 8) |
| | **Υγεία HPE iLO / Redfish** | υγεία υλικού διακομιστή από το BMC (iLO 4/5/6, iDRAC, άλλα BMC με Redfish) |
| | **Θερμοκρασία εισόδου (iLO / Redfish)** | θερμοκρασία του αέρα που μπαίνει στον server, δηλαδή μπροστά στο rack: Υποβαθμισμένο από 27 °C, εκτός λειτουργίας από 32 °C (ASHRAE), με διάγραμμα |
| | **Θερμοκρασία αίθουσας** | όλοι οι αισθητήρες εισόδου με ετικέτα `room:<name>` μαζί: εκτός λειτουργίας όταν πολλοί είναι ζεστοί (πρόβλημα ψύξης), υποβαθμισμένο όταν ένας είναι ζεστός ή πολλοί ανεβαίνουν γρήγορα |
| Παθητικός | **Push heartbeat** | μια εργασία καλεί ένα URL· Εκτός λειτουργίας όταν σταματήσει να καλεί |
| | **SNMP traps** | traps που στέλνει μια συσκευή (v1, v2c): εκτός λειτουργίας ή υποβαθμισμένη όσο υπάρχει ανοιχτό trap προβλήματος· κλείνει μόνο του, με trap κλεισίματος ή με το χέρι |

Η **Δοκιμή τώρα** εκτελεί έναν έλεγχο μία φορά από τον διακομιστή του Fudo χωρίς αποθήκευση,
ώστε να τον ρυθμίσετε πριν αρχίσει να στέλνει ειδοποιήσεις.

## Αποφυγή ψευδών συναγερμών

- **Εκτός λειτουργίας μετά από N αποτυχίες**: μια παρακολούθηση γίνεται Εκτός λειτουργίας μόνο
  μετά από N διαδοχικούς αποτυχημένους ελέγχους, με επανάληψη στο ταχύτερο *διάστημα
  επανάληψης* ενδιάμεσα.
- **Σε λειτουργία μετά από M επιτυχίες**: επανέρχεται μόνο μετά από M διαδοχικούς επιτυχείς
  ελέγχους.
- **Υποβαθμισμένο πάνω από**: οι αργές αποκρίσεις μετρούν ως Υποβαθμισμένο αντί για Εκτός
  λειτουργίας.

## Διαπιστευτήρια

Κωδικοί πρόσβασης, κοινότητες SNMP, κλειδιά SSH και παρόμοια αποθηκεύονται **κρυπτογραφημένα**
και δεν εμφανίζονται ξανά, δεν εξάγονται και δεν επιστρέφονται από το API· μόνο ο worker τα
αποκρυπτογραφεί για να εκτελέσει έναν έλεγχο. Χρησιμοποιήστε λογαριασμούς μόνο για ανάγνωση:
ρόλο vCenter με *Read-only*, χρήστη iLO με το δικαίωμα *Login*, χρήστη βάσης δεδομένων μόνο με
`CONNECT`/`SELECT`.

### Κοινά διαπιστευτήρια

Όταν πολλές παρακολουθήσεις συνδέονται με τον ίδιο λογαριασμό (ένας χρήστης iLO μόνο για ανάγνωση
σε όλους τους διακομιστές, μία κοινότητα SNMP για τους μεταγωγείς), κρατήστε τον μία φορά στα
**Διαπιστευτήρια** και αφήστε τις παρακολουθήσεις να τον χρησιμοποιούν. Όταν αλλάξει ο κωδικός,
επεξεργαστείτε τα διαπιστευτήρια μία φορά: κάθε παρακολούθηση που τα χρησιμοποιεί ελέγχει αμέσως
ξανά με τη νέα τιμή.

- Τα διαπιστευτήρια έχουν είδος: *Λογαριασμός και κωδικός*, *Κλειδί SSH*, *Κοινότητα SNMP (v1,
  v2c)* ή *Χρήστης SNMPv3*. Στη φόρμα παρακολούθησης, οι τύποι που συνδέονται προσφέρουν
  **Καταχώριση εδώ** ή **Χρήση κοινών διαπιστευτηρίων**· με διαπιστευτήρια, τα πεδία λογαριασμού
  εξαφανίζονται από τη φόρμα.
- Τα διαπιστευτήρια ανήκουν σε ένα πεδίο: οι παρακολουθήσεις ενός μισθωτή χρησιμοποιούν μόνο τα
  διαπιστευτήρια αυτού του μισθωτή, και οι παρακολουθήσεις του πεδίου γενικής υποδομής μόνο τα
  καθολικά.
- Τα μυστικά είναι μόνο για εγγραφή, όπως και μιας παρακολούθησης: αποθηκεύονται
  κρυπτογραφημένα και δεν εμφανίζονται, δεν εξάγονται και δεν επιστρέφονται ποτέ. Η λίστα δείχνει
  τον λογαριασμό και ποιες παρακολουθήσεις τον χρησιμοποιούν.
- **Ίδιος λογαριασμός σε πολλές παρακολουθήσεις**: η σελίδα δείχνει παρακολουθήσεις που ήδη
  αποθηκεύουν τον ίδιο λογαριασμό και κωδικό. Δώστε όνομα στην ομάδα και επιλέξτε **Δημιουργία
  κοινών διαπιστευτηρίων**: ο κωδικός αντιγράφεται στον διακομιστή, δεν χρειάζεται να τον ξέρει
  κανείς.
- Το **Χρήση για…** συνδέει περισσότερες παρακολουθήσεις με τα διαπιστευτήρια· ο δικός τους
  λογαριασμός και κωδικός αφαιρούνται. Διαπιστευτήρια σε χρήση δεν διαγράφονται και το είδος τους
  δεν αλλάζει.
- Μια παρακολούθηση που σταματά να χρησιμοποιεί διαπιστευτήρια χρειάζεται ξανά δικό της κωδικό.
- Στη [ρύθμιση ως κώδικα](configuration-as-code.md) μια παρακολούθηση αναφέρει τα διαπιστευτήριά
  της (`credential: iLO read-only`)· τα ίδια τα διαπιστευτήρια δημιουργούνται στη διεπαφή. Και η
  μαζική προσθήκη ελέγχων θερμοκρασίας μπορεί να τα χρησιμοποιήσει.
- Κάθε αλλαγή καταγράφεται στο αρχείο ελέγχου, με τα ονόματα των μυστικών που άλλαξαν, ποτέ με τις
  τιμές τους.

## Παρακολουθήσεις push

Μια παρακολούθηση push περιμένει να την καλέσει η εργασία σας. Μετά την αποθήκευση, η σελίδα
της δείχνει το URL:

```bash
curl -fsS "https://fudo.corp.local/api/push/<token>?msg=backup%20ok&ping=5400"   # success
curl -fsS "https://fudo.corp.local/api/push/<token>?status=down&msg=disk%20full" # report a failure
```

Γίνεται Εκτός λειτουργίας όταν δεν φτάσει κλήση μέσα στο διάστημα και την περίοδο χάριτος. Το
**Νέο URL** αντικαθιστά το διακριτικό αν διέρρευσε.

## Μαζική προσθήκη και πρότυπα

Η **Μαζική προσθήκη / πρότυπα** στις **Παρακολουθήσεις** δημιουργεί ελέγχους για πολλούς
υπολογιστές μαζί:

1. επικολλήστε ένα host ή URL ανά γραμμή (ή φορτώστε ένα CSV με `name,host,port`),
2. επιλέξτε ένα **πρότυπο**, για παράδειγμα *διακομιστής Windows* (ping, RDP, WinRM),
   *διακομιστής Linux*, *HPE iLO*, *συσκευή δικτύου*, *host ESXi*, *vCenter*, *SQL Server*,
   *αποθηκευτικό σύστημα* ή *εφαρμογή ιστού*, ή έναν μεμονωμένο τύπο ελέγχου,
3. προαιρετικά δημιουργήστε έναν πόρο ανά γραμμή, κάντε τους να εξαρτώνται από έναν υπάρχοντα
   πόρο και προσθέστε τους σε μια εφαρμογή.

Πριν την εφαρμογή δείχνει προεπισκόπηση όλων όσων θα δημιουργήσει.

## Σημειώσεις ανά τύπο

- Το **VM vCenter** βρίσκει μόνο του τη σωστή έκδοση API και επαναχρησιμοποιεί τις συνεδρίες
  (μία σύνδεση ανά vCenter κάθε 20 λεπτά). Ο έλεγχος VMware Tools απαιτεί vCenter 7.0 ή
  νεότερο.
- Το **HPE iLO / Redfish** κατονομάζει το εξάρτημα που έχει βλάβη στο HPE iLO (ανεμιστήρες,
  τροφοδοτικά, αποθήκευση, πλεονασμός). Warning → Υποβαθμισμένο, Critical ή απενεργοποιημένος
  → Εκτός λειτουργίας.
- **Εντολή SSH**: ορίστε το *Αποτύπωμα κλειδιού host* (`ssh-keyscan host | ssh-keygen -lf -`)
  ώστε ένα αλλαγμένο κλειδί διακομιστή να αναφέρεται αντί να γίνεται αποδεκτό.
- Το **Container Docker** χρησιμοποιεί το τοπικό socket του Docker (προσαρτήστε το στο
  container του worker, δείτε το `docker-compose.yml`) ή ένα απομακρυσμένο URL του Docker API.
- **Λήξη τομέα**: ορισμένα εθνικά μητρώα δεν δημοσιεύουν ούτε RDAP ούτε WHOIS· το Fudo το
  αναφέρει ως Υποβαθμισμένο με εξήγηση.
- Το **Ping** χρειάζεται τη δυνατότητα `NET_RAW` στο container του worker, και στο container
  του API για τη **Δοκιμή τώρα** (ορίζονται και οι δύο στο `docker-compose.yml`).

## SNMP traps

Στείλτε τα SNMP traps (v1 ή v2c) των συσκευών σας στον διακομιστή Fudo, θύρα UDP 162. Η σελίδα
**Traps** δείχνει αν λαμβάνονται traps, και κάθε trap με τα πεδία του.

- Μια παρακολούθηση **SNMP traps** παίρνει τα traps των συσκευών στο **Από**: διευθύνσεις,
  ονόματα host ή εύρη IPv4 (`10.0.12.0/24`). Με **Κοινότητα** (ή κοινά διαπιστευτήρια τύπου
  κοινότητας SNMP) παίρνει μόνο traps που τη φέρουν· η κοινότητα δεν αποθηκεύεται ποτέ.
- **Traps προβλήματος**: τα βασικά (link down, ψυχρή και θερμή εκκίνηση, αποτυχία
  ταυτοποίησης), μόνο τα traps της λίστας (ονόματα ή OID· ένα OID καλύπτει και ό,τι βρίσκεται
  κάτω από αυτό, π.χ. το πρόθεμα enterprise ενός κατασκευαστή) ή οποιοδήποτε trap. Το *Μόνο όταν
  ένα πεδίο περιέχει* περιορίζει σε traps με ένα κείμενο όπως `Critical`.
- Όσο ένα πρόβλημα είναι ανοιχτό, η παρακολούθηση είναι **Εκτός λειτουργίας** (ή Υποβαθμισμένη,
  αν το επιλέξετε)· συμβάν, ειδοποιήσεις και εφημερίες λειτουργούν όπως σε κάθε έλεγχο, μέσα σε
  ένα δευτερόλεπτο από το trap.
- Τα προβλήματα κρατιούνται ανά trap και διεπαφή: link down σε δύο θύρες είναι δύο προβλήματα,
  και το **link up** μιας θύρας κλείνει μόνο το πρόβλημα αυτής της θύρας.
- **Τα προβλήματα κλείνουν** αυτόματα όταν δεν έρχεται νέο trap για λίγο (προεπιλογή 30
  λεπτά), ή μόνο με το χέρι: η σελίδα της παρακολούθησης δείχνει τα ανοιχτά traps με
  **Εκκαθάριση** (μέχρι το επόμενο αντίστοιχο trap). Και τα *traps κλεισίματος* κλείνουν
  προβλήματα, π.χ. το trap «η κατάσταση αποκαταστάθηκε» ενός κατασκευαστή.
- Ένα trap που **δεν παίρνει καμία παρακολούθηση** κρατιέται κι αυτό: στον μισθωτή του πόρου με
  αυτή τη διεύθυνση, αλλιώς στο πεδίο γενικής υποδομής. Η **Δημιουργία παρακολούθησης** στη
  σελίδα Traps συμπληρώνει μια παρακολούθηση για τη συσκευή του.
- Μια συσκευή που πλημμυρίζει με traps περιορίζεται (50 ανά δευτερόλεπτο, αιχμές έως 500)· τα
  traps που απορρίφθηκαν μετρώνται στη σελίδα Traps του γενικού πεδίου. Τα traps κρατιούνται 30
  ημέρες (Ρυθμίσεις › Διατήρηση δεδομένων).

## Διεπαφές δικτύου

Μια παρακολούθηση **Διεπαφή δικτύου (SNMP)** παρακολουθεί μία θύρα ενός μεταγωγέα, δρομολογητή ή
τείχους προστασίας.

- Η **Εύρεση διεπαφών…** (μετά τον host και την πρόσβαση SNMP, ή κοινά διαπιστευτήρια) εμφανίζει
  τις διεπαφές της συσκευής με περιγραφή, ταχύτητα και κατάσταση. Επιλέξτε μία ή, κατά την
  προσθήκη, σημειώστε περισσότερες: η καθεμία γίνεται παρακολούθηση με τις ρυθμίσεις της φόρμας,
  με το όνομα της διεπαφής.
- Η διεπαφή κρατιέται με το **όνομά** της (ή την περιγραφή ή το ψευδώνυμο), όχι με τον αριθμό,
  γιατί κάποιες συσκευές αλλάζουν την αρίθμηση των διεπαφών μετά από επανεκκίνηση. Και ένας
  αριθμός λειτουργεί.
- Η **κίνηση** είναι η διαφορά δύο μετρήσεων των μετρητών 64 bit: ο πρώτος έλεγχος μετρά δύο φορές
  με απόσταση δύο δευτερολέπτων· οι επόμενοι χρησιμοποιούν τη μέτρηση που κρατήθηκε από τον
  προηγούμενο έλεγχο. Μετά από επανεκκίνηση της συσκευής το ζεύγος παραλείπεται, οπότε δεν
  υπάρχει ψευδής αιχμή. Συσκευές χωρίς μετρητές 64 bit (SNMP v1) χρησιμοποιούν μετρητές 32 bit,
  που δεν είναι αξιόπιστοι πάνω από περίπου 100 Mbit/s με διάστημα ενός λεπτού.
- **Κατάσταση**: η σύνδεση έπεσε → Εκτός λειτουργίας· testing ή dormant → Υποβαθμισμένο· μια θύρα
  σκόπιμα απενεργοποιημένη είναι Σε λειτουργία (ή Εκτός λειτουργίας, αν το επιλέξετε). Η πιο
  φορτωμένη κατεύθυνση πάνω από το *Υποβαθμισμένο από χρήση* (προεπιλογή 80 %) → Υποβαθμισμένο,
  πάνω από το *Εκτός λειτουργίας από χρήση* (απενεργοποιημένο από προεπιλογή) → Εκτός
  λειτουργίας· σφάλματα ανά λεπτό πάνω από το όριο → Υποβαθμισμένο. Αν η συσκευή αναφέρει λάθος
  ταχύτητα (ένα tunnel, ένα κύκλωμα με όριο ρυθμού), ορίστε την *Ταχύτητα σύνδεσης*.
- Η σελίδα της παρακολούθησης δείχνει την εισερχόμενη και εξερχόμενη κίνηση με τη γραμμή του
  Υποβαθμισμένου.
- Η *Σύγκριση: η μεταβολή της ανά δευτερόλεπτο* της παρακολούθησης **SNMP** κάνει το ίδιο για
  οποιονδήποτε μετρητή (πλαίσια σε θύρα SAN, συνεδρίες τείχους προστασίας, συμβάντα UPS).

## Θερμοκρασία data center

Η **Θερμοκρασία** δείχνει κάθε αισθητήρα θερμοκρασίας εισόδου, ομαδοποιημένο με την ετικέτα `room:<name>` και ταξινομημένο από τον θερμότερο, με το rack του (`rack:<name>`), την τρέχουσα τιμή, τις τελευταίες 6 ώρες, τη μεταβολή 15 λεπτών και το εύρος 24 ωρών. Η **Προσθήκη αισθητήρων** τους δημιουργεί για μια λίστα διευθύνσεων iLO (ή άλλου BMC Redfish) με έναν κοινό λογαριασμό μόνο ανάγνωσης.

Ένας αισθητήρας γίνεται επίσης υποβαθμισμένος όταν η θερμοκρασία του **ανεβαίνει γρήγορα** (από προεπιλογή 3 °C μέσα σε 15 λεπτά), ακόμη και κάτω από τα όρια: το πρώτο σημάδι βλάβης ψύξης. Η **Δημιουργία ειδοποίησης αίθουσας** προσθέτει μια παρακολούθηση *Θερμοκρασία αίθουσας*: εκτός λειτουργίας όταν 3 αισθητήρες είναι ζεστοί, υποβαθμισμένο όταν ένας είναι ζεστός ή 2 ανεβαίνουν γρήγορα. Ανοίγει συμβάντα όπως κάθε παρακολούθηση, οπότε ιδιοκτησία, βάρδιες και σελίδες κατάστασης λειτουργούν και γι’ αυτήν.
